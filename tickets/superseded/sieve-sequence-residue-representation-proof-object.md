# Sieve Sequence Residue Representation Proof Object

**Created:** 2026-06-15
**Status:** First prototype verified

---

## Goal

Try the alternate proof strategy in a separate object: make the semantic
meaning of `SieveSequenceV2` explicit as a finite residue representation, so
Stainless can use "values in this cycle are not multiples of any listed prime"
as a structural fact rather than rediscovering it from the walk.

---

## Current State

- `just verify` passes at 5347 valid, 0 invalid, 0 unknown.
- `SieveSequenceV2.next()` still uses `@extern`.
- The currently isolated constructor-requirement helpers verify through the
  first new-head coprimality requirement.
- `SieveSequenceByPrimes` now defines a prime-list-only semantic baseline:
  `head`, `wheelPrimes`, `modulus`, and `accepts`.
- `SieveSequenceByPrimes.acceptsPrimeList` bridges `List[Prime]` into the
  semantic baseline through `PrimeUtils.primeValues`.
- The remaining bottleneck is still expected to be `gaps.nonEmpty` for
  `nextGapCycleV2`.

---

## Expected State

Create a separate proof object, likely near `v1.seq.sieve.properties`, that
captures small residue-representation lemmas without modifying `MemCycle`,
`ModCycle`, `CycleIntegral`, or the `SieveSequenceV2` constructor.

The first prototype should avoid proving the full representation at once.
Instead, add one lemma at a time:

1. Residues generated by `SieveUtils.residues(M, primes)` are coprime to
   `primes`.
2. Adding `M = product(primes)` preserves non-divisibility by each prime in
   `primes`.
3. A candidate known to be coprime to `primes` remains coprime after adding
   `M`.
4. Use those lemmas to express the survivor-existence argument for the next
   gap list.

## Risks

- Full "cycle represents exactly all coprime residues" may be too broad for one
  Stainless proof.
- Computing `SieveUtils.residues` inside a constructor could cause VC explosion;
  this experiment should stay outside the constructor.
- The proof must not hide the hard step: preservation across old primes is not
  enough by itself; non-empty also needs the new-head filter argument.

---

## Assumptions And Validation

- Assumption: residue-representation lemmas can be verified in a separate object
  before changing the sequence data model.
  - Validate by adding one `.holds` lemma and running `just verify`.
- Assumption: adding `product(primes)` preserves coprimality to `primes`.
  - Validate through a recursive helper over the prime list using `Calc.mod`.
- Final validation: sieve tests first, then `just verify`, with valid count same
  or higher than 5340.
