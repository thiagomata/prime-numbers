## Goal

Run the experiment the single-transition window pass structurally could not: fix a future square window `W_Q = [Q, Q^2)`, take its 2-gap population at an earlier stage, and apply every intermediate prime filter `r < Q` one layer at a time, measuring at each layer the *actual stated condition* of candidates #4, #10, #12, #13, #14. This tests whether successive filters can cherry-pick the population near the future head — the core of #14's hereditary claim — and retrofits the correct tests for the others.

**Success criterion for the first run (per user decision): measure correctly first.** The pilot's job is to produce per-layer measurements validated by hand-checks, NOT to reach a verdict on any candidate. Verdicts come later from analyzing correct data.

## Confirmed Design Decisions (user, 2026-07-23)

1. **Small-Q pilot, then scale.** Build and validate at a tiny Q before any expensive run. Catches indexing/convention errors cheaply (the window pass caught the p=3 and gaps.csv errors this way).
2. **Measure correctly first.** No premature verdict loaded onto a single Q's data.
3. **Reading A — actual accepted set per layer.** Each layer's population is the integers in `[Q,Q^2)` coprime to all primes below the current layer's head, updated as filters install. This is the real sieve. Reading B (frozen earliest population) is explicitly rejected — it would measure the wrong process.

## Critical Design Finding (must not be papered over)

Reading the hereditary note carefully exposes a **scale tangle** the window pass did not confront:

- The per-layer quantity `sigma_r(k)` (min span of k consecutive shots) is defined over the **complete period** of the stage: modulus `M_r`, all `T_r` cofactor residues, periodic indexing (hereditary note lines 68-80). It is a whole-period object.
- The lineage experiment wants per-layer `sigma_r`, but `sigma_r` is itself only exactly computable while `M_r` is small — i.e. for the first few layers of a small Q.
- The sufficiency condition needs an interval `J_r subset [Q,Q^2)` with `G_r(J_r) >= k_r` AND `len(J_r) < sigma_r(k_r)`. The window-local count `G_r(J_r)` is feasible at any scale; the `sigma_r(k_r)` bound is the hard whole-period part.

**Consequence for design:** at the pilot Q (small, `M_r` tractable), `sigma_r(k)` can be computed EXACTLY — this is the pilot's value and the reason a small-Q pilot is mandatory. At larger Q, exact `sigma_r` becomes infeasible and the experiment must either (a) stop scaling once `M_r` exceeds a tractable bound, or (b) introduce an explicit lower-bound estimate for `sigma_r` flagged as an estimate, not the exact quantity. **Decision: do (a) for the pilot — measure exact `sigma_r` only as far as `M_r` is tractable, and report the exact-coverage frontier honestly. Do not substitute a whole-window proxy for `sigma_r`; that is precisely the error the review caught last pass.**

## Per-Layer Measurement List

At each layer (installing filter `r`, current accepted set = integers in `[Q,Q^2)` coprime to all primes `< r`):

- `G_r(W_Q)` — complete 2-gaps in the window before filter `r` (window-local, exact).
- `destroyed_r` — 2-gaps destroyed by installing `r` (x or x+2 = 0 mod r), exact.
- `surviving_r` — 2-gaps after installing `r`, exact.
- **#4 cyclic destroyed run:** longest run of consecutively-destroyed 2-gap starts over the **cyclic ordering** (period modulus `M_r`), NOT the window-linear order. (See open question below.)
- **#14 `sigma_r(k)`** — min span of k consecutive shots, computed exactly from the full period `M_r` where tractable; reported only within the exact-coverage frontier.
- **#14 interval search:** does there exist `J_r subset [Q,Q^2)` and `k_r` with `G_r(J_r) >= k_r` and `len(J_r) < sigma_r(k_r)`? (The actual per-layer premise, not the whole-window waste ratio.)
- **#10 post-filter discrepancy:** `E_q = |S_q ∩ W_q| − main_term`, using the **post-filter** count this time (correcting the pre/post error).
- **#12 margin:** the candidate's own sufficient condition `nu E < N(1 - nu/p)` (not the sqrt normalization).
- **#13 one-sided margin:** `H(2L/N + b_+) < L` where `b_+` is the harmful one-sided bias (not absolute bias).

## Open Design Question (to resolve in implementation, surfaced not hidden)

**#4's "cyclic" destroyed run over what modulus?** The candidate states the run over the cyclic ordering of 2-gap starts. In the window pass I measured the window-linear run and the review correctly flagged the mismatch. But in the lineage experiment the population is a *window* `[Q,Q^2)`, not a full period — so "cyclic" is ambiguous: cyclic over the window (treating the window as a cycle) or cyclic over the full period `M_r` (which may be much larger than the window)? These differ and give different numbers.

Plan: compute BOTH at the pilot (cheap at small Q), document which matches the candidate's intent by re-reading #4's note against the data, and record the choice. Do not silently pick one.

## Validation (green gate)

`test_lineage.py` (stdlib assert, exit code, verify.py style) must pass before scaling. It enforces:
- **Hand-derived layer 0 and layer 1** at the pilot Q: survivor lists, G_r, destroyed, surviving written out by hand (independent of the code), matched exactly.
- **Structural identities per layer:** `destroyed + surviving == G_r`; `surviving >= 0`; population at layer r+1 = population at layer r minus filter-r hits (Reading A consistency check).
- **`sigma_r` self-consistency:** `sigma_r(2) == min shot gap`; `sigma_r(T_r) == r*M_r` (full period span); monotonic in k.
- **Cyclic vs window-linear run** reported separately at the pilot so the open question above is decided from data, not assumption.

Small-changes: add ONE per-layer measurement -> tests green -> next. Red-cascade: revert the single failing change.

Record the exact-coverage frontier.
2. `lib_lineage.py`: pure functions. `accepted_set(Q, primes_below_r)`, `cofactor_gaps_and_period(...)`, `sigma_r(k)`, cyclic + window-linear destroyed runs, post-filter E_q, #12/#13 margins.
3. `test_lineage.py`: hand-derived layers 0-1 at Q=17, identities, sigma self-consistency.
4. `run_lineage.py`: thin runner, one row per layer to `data/candidates/lineage-Q17.csv`.
5. Run pilot, validate, write FINDINGS_lineage.md.
6. Only after pilot green: consider scaling Q (and hit the exact-coverage frontier honestly).

## Out of Scope

- No Scala/Stainless/Spark (decoupled Python, same as the window pass).
- No verdict on any candidate from the pilot alone (measure correctly first).
- No substitution of whole-window proxies for whole-period quantities (the error that motivates the careful `sigma_r` handling above).
- Formal-verification gap remains a separate effort.
