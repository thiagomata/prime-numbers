## Abstract

This draft records the small bridge between the foundational arithmetic
articles and the full sieve-sequence specification. The full sieve sequence is
studied in [Formal Verification of Sieve Sequence Stages and Their
Transitions](https://github.com/thiagomata/prime-numbers/blob/master/articles/chapter6/sieve-sequence.md). This draft stops earlier: it
isolates the two primitive facts that make a sieve plausible before period,
gap-cycle, and transition semantics enter the picture.

First, a cycle integral over the unit cycle `[1]` generates consecutive
candidate integers. Second, filtering by a prime never removes any different
prime. Together, these facts say that the initial candidate stream is complete
and that the elementary filtering operation is prime-preserving.

## 1. Scope

This draft is a bridge article. It does not prove the complete sieve-sequence
transition, next-period size, gap reconstruction, next-head theorem, or any
2-gap survival result. Those belong to the active sieve-sequence and
gap-dynamics articles.

The goal here is narrower:

1. show that the unit gap cycle generates consecutive integers;
2. show that this generated stream is strictly increasing;
3. show that two distinct primes do not divide each other;
4. show that filtering by one prime preserves every other prime;
5. show that a filtered list still contains every original prime not equal to
   the filter prime.

These are foundation lemmas. They are small enough to understand on their own,
but important enough that hiding them inside the full sieve-sequence article
makes the reader jump too quickly from arithmetic primitives to stage
transitions.

## 2. Unit-Cycle Candidate Generation

The sieve starts from a stream of candidates. In the cycle-integral
representation, the simplest stream is generated by the unit cycle `[1]`.
Every step adds one, so the generated values are consecutive.

For a nonnegative initial value `init`, define:

```math
\begin{aligned}
C &= \text{MemCycle}([1]), \\
I &= \text{CycleIntegral}(init, C).
\end{aligned}
```

Then for every position `i >= 0`:

```math
\begin{aligned}
I(i) &= init + i + 1.
\end{aligned}
```

The proof is induction on `i`. At position zero, the cycle contributes one
step, so `I(0) = init + 1`. At the next position, the same cycle again
contributes one, so the induction hypothesis advances by exactly one.

```scala
def assertCycleIntegralOfOnes(init: BigInt, pos: BigInt): Boolean = {
  require(pos >= 0)
  require(init >= 0)
  val cycle = MemCycle(stainless.collection.List(BigInt(1)))
  val ci = CycleIntegral(init, cycle)
  decreases(pos)
  if (pos == 0) {
    ci(0) == init + BigInt(1)
  } else {
    assert(assertCycleIntegralOfOnes(init, pos - 1))
    ci(pos) == init + pos + BigInt(1)
  }
}.holds
```

This property is verified in
[CycleIntegralOnesProperties::assertCycleIntegralOfOnes](https://github.com/thiagomata/prime-numbers/blob/master/src/main/scala/v1/chapter4/cycle/integral/recursive/properties/CycleIntegralOnesProperties.scala).

## 3. Unit-Cycle Strict Increase

Because the unit cycle adds one at every step, later positions are strictly
larger than earlier positions. This is the ordered-candidate part of the
foundation: the stream does not stall, repeat, or move backward.

For `0 <= a < b`:

```math
\begin{aligned}
I(a) &= init + a + 1, \\
I(b) &= init + b + 1, \\
b>a &\Longrightarrow I(b)>I(a).
\end{aligned}
```

```scala
def assertCycleIntegralOfOnesStrictlyIncreasing(
  init: BigInt,
  a: BigInt,
  b: BigInt
): Boolean = {
  require(a >= 0)
  require(b > a)
  require(init >= 0)
  val cycle = MemCycle(stainless.collection.List(BigInt(1)))
  val ci = CycleIntegral(init, cycle)
  assert(assertCycleIntegralOfOnes(init, a))
  assert(assertCycleIntegralOfOnes(init, b))
  ci(b) > ci(a)
}.holds
```

This property is verified in
[CycleIntegralOnesProperties::assertCycleIntegralOfOnesStrictlyIncreasing](https://github.com/thiagomata/prime-numbers/blob/master/src/main/scala/v1/chapter4/cycle/integral/recursive/properties/CycleIntegralOnesProperties.scala).

## 4. Distinct Primes Do Not Divide Each Other

Filtering by a prime is safe only because primes do not divide different
primes. If `q` and `p` are both prime and `q != p`, then `p` cannot divide
`q`.

```math
\begin{aligned}
\text{isPrime}(q)
\land \text{isPrime}(p)
\land q \neq p
&\Longrightarrow
\text{mod}(q,p) \neq 0.
\end{aligned}
```

There are two cases. If `q > p`, primality of `q` says no value in `[2,q)`
divides `q`; since `p` lies in that range, `mod(q,p) != 0`. If `q < p`, then
`q` is a small dividend modulo `p`, so `mod(q,p) = q`, and a prime `q` is
nonzero.

```scala
def assertPrimeNotDivisibleByDistinctPrime(q: BigInt, p: BigInt): Boolean = {
  require(q >= 2)
  require(p >= 2)
  require(Prime.isPrime(q))
  require(Prime.isPrime(p))
  require(q != p)
  if (q > p) {
    assert(noDivisorInRangeImpliesModNonZero(q, 2, q, p))
    Calc.mod(q, p) != BigInt(0)
  } else {
    assert(ModSmallDividend.modSmallDividend(q, p))
    Calc.mod(q, p) != BigInt(0)
  }
}.holds
```

This property is verified in
[FilterPreservesPrimesProperties::assertPrimeNotDivisibleByDistinctPrime](https://github.com/thiagomata/prime-numbers/blob/master/src/main/scala/v1/chapter5/prime/properties/FilterPreservesPrimesProperties.scala).

## 5. Corollary: The Filter Reading

The previous section proves a single prime survives the filter test. This
section is the same proposition read in filter vocabulary: it renames the
divisor `p` of §4 to `filterPrime` and keeps the verified Scala wrapper
because it is the form the sieve consumes. Filtering by `filterPrime`
removes values divisible by `filterPrime`; a different prime `q` is not
divisible by `filterPrime`, so it survives the divisibility test.

```math
\begin{aligned}
\text{isPrime}(q)
\land \text{isPrime}(\text{filterPrime})
\land q \neq \text{filterPrime}
&\Longrightarrow
\text{mod}(q,\text{filterPrime}) \neq 0.
\end{aligned}
```

```scala
def assertFilterPreservesAllPrimes(
  q: BigInt,
  filterPrime: BigInt
): Boolean = {
  require(q >= 2)
  require(filterPrime >= 2)
  require(Prime.isPrime(q))
  require(Prime.isPrime(filterPrime))
  require(q != filterPrime)
  assert(assertPrimeNotDivisibleByDistinctPrime(q, filterPrime))
  Calc.mod(q, filterPrime) != BigInt(0)
}.holds
```

This property is verified in
[FilterPreservesPrimesProperties::assertFilterPreservesAllPrimes](https://github.com/thiagomata/prime-numbers/blob/master/src/main/scala/v1/chapter5/prime/properties/FilterPreservesPrimesProperties.scala).

## 6. Filtered Lists Still Contain The Surviving Primes

The previous section proves a single prime survives the filter test. The list
property lifts that local fact to a structural statement: if `q` was present in
the original list and is not the filter prime, then `q` is still present after
filtering.

```math
\begin{aligned}
q \in L
\land \text{isPrime}(q)
\land \text{isPrime}(p)
\land q \neq p
&\Longrightarrow
q \in \text{filterList}(L,p).
\end{aligned}
```

The proof is induction on the list. If the head is `q`, the previous lemma
shows the filter keeps it. If `q` is in the tail, the induction hypothesis
keeps it in the filtered tail.

```scala
def assertFilteredContainsAllPrimes(
  originalPrimes: List[BigInt],
  filterPrime: BigInt,
  q: BigInt
): Boolean = {
  require(filterPrime >= 2)
  require(Prime.isPrime(filterPrime))
  require(q >= 2)
  require(Prime.isPrime(q))
  require(q != filterPrime)
  require(originalPrimes.contains(q))
  decreases(originalPrimes.size)
  if (originalPrimes.isEmpty) {
    false
  } else {
    val filtered = CoprimeUtils.filterList(originalPrimes, filterPrime)
    if (originalPrimes.head == q) {
      assert(assertFilterPreservesAllPrimes(q, filterPrime))
      filtered.contains(q)
    } else {
      assert(assertFilteredContainsAllPrimes(
        originalPrimes.tail,
        filterPrime,
        q
      ))
      filtered.contains(q)
    }
  }
}.holds
```

This property is verified in
[FilterPreservesPrimesProperties::assertFilteredContainsAllPrimes](https://github.com/thiagomata/prime-numbers/blob/master/src/main/scala/v1/chapter5/prime/properties/FilterPreservesPrimesProperties.scala).

## 7. What This Bridge Gives The Sieve

The five verified properties above — four substantively distinct lemmas,
with §5 as the filter-reading corollary of §4 — give the candidate/filter
foundation:

```math
\begin{aligned}
\text{CycleIntegral}(init,[1])_i
&= init+i+1,
&&\text{[candidate generation]} \\
b>a
&\Longrightarrow I(b)>I(a),
&&\text{[ordered candidates]} \\
\text{isPrime}(q)
\land \text{isPrime}(p)
\land q\neq p
&\Longrightarrow \text{mod}(q,p)\neq0,
&&\text{[distinct primes survive divisibility]} \\
q\in L
\land \text{isPrime}(q)
\land q\neq p
&\Longrightarrow q\in \text{filterList}(L,p).
&&\text{[prime-preserving filter]}
\end{aligned}
```

This is the basic correctness shape of the sieve mechanism: the starting
stream can enumerate candidates in order, and a prime filter does not remove
any other prime. The active sieve-sequence article builds on this foundation
and studies the stronger finite-period object: complete accepted-value
enumeration, periodic block shifts, gap-cycle reconstruction, exact expanded
filtering, copy-or-merge gap transitions, and conditional next-stage
reconstruction.

## 8. Boundary

This draft does not claim that a particular sieve-stage head is prime, that a
new period has a particular size, or that a gap survives in any local window.
Those are stronger statements that require the full sieve-sequence object,
prime-prefix completeness, and transition proofs.

The bridge here is deliberately small: it explains why the primitive actions
"generate consecutive candidates" and "remove multiples of a prime" are the
right starting point for a formally verified sieve.
